## 2026-10-22 存档槽事务修复（分支 `fix/save-reliability-20261022`）

### 修复内容

1. **剧情存档回退不再删除原档。** 旧 `RollBack()` 以"备份文件是否存在"推断槽位
   原本是否为空：备份缺失时删除原生档。现在写入前把每个参与文件的存在性与
   SHA-256 记录进 `<槽>.dat.mhtx` 事务日志，回退只按记录执行；备份缺失或损坏
   时在写入任何文件之前拒绝，并把日志置为 `broken`、保留日志、备份与中断标记。
2. **普通原生档覆盖实验槽的崩溃窗口。** 覆盖前先开启 `supersede` 事务；原生档
   写入并校验通过后先记录可信替换哈希，再退役旧附档。崩溃在清理前时，下次读档
   /存档按该哈希"向前完成"清理，而不是留下会让有效原生档被拒读的旧附档。
3. **附档与原生档不匹配的判定。** `-required` 标记仍在时视为不可判定的歧义并
   拒绝；标记不在时把附档改名为 `.stale` 保留并按原生档载入，状态栏说明当前
   位于原生检查点而非精确恢复点。
4. **删除槽位。** 游戏只删除 `.dat`，附档会残留导致该槽再也无法保存；现在
   `DeleteSaveData` 之后清理附档与事务日志，并对空槽上的孤立附档做清理。
5. **恢复锁作用域。** 自动存档与 `LuaManager.PrologueSave` 的原生恢复也会调用
   `ExecuteLoadGameData`，旧补丁为它们抢占恢复锁且永不解锁，会导致整局无法存档
   与调速。现在只接管编号手动读档；60 秒内没有等到场景加载时标记恢复失败，保留保护锁，需重新读取有效原生档。
6. **输入锁统一。** 剧情与单挑各自维护"我禁用了哪些输入模块"的列表，后取得锁的
   一方不会记录已被对方禁用的模块，先解锁的一方便会在另一次恢复仍在进行时恢复
   输入。改为单一持有者集合（`InteractionLock`）。
7. **诊断。** 失败时记录存档位置、恢复阶段、最后成功重放的事件、出错事件、实际
   与记录的脚本名、事务状态与回滚阻塞原因。定位不到的值写成 `<none>`，不作为
   默认值参与任何成功判定。
8. **回放超时改为按停顿判定。** 旧逻辑从读档瞬间起算 120 秒，长流程或多回合单挑
   即使一直在推进也会被判超时。现在只在"超过两分钟没有任何新事件/行动点"时中止，
   并把已重放数量写进失败信息。

完整设计、状态机与逐情形结果见 [存档槽事务设计](SAVE-TRANSACTION.md)。

### 本机实机验收步骤

测试前备份 `%LOCALAPPDATA%Low\Obb Studio\Mortal\<steamid>` 整个目录，并使用
不常用的编号槽（例如 `099`）。每个场景重复完整链路，并记录 BepInEx 日志。

1. **普通原生档不回归**：编号槽正常保存 → 退到标题 → 读取 → 存档面板可用。
2. **剧情·台词等待**：一句普通台词处创建随时存档 → 完全退出 → 重启 → 读取 →
   应停在**同一句台词**，属性/关系/物品与存档时一致 → 继续推进一句 → 再存档。
3. **剧情·选项等待**：选项界面创建存档 → 重启读取 → 应停在**同一组选项**且
   不自动选中 → 选择后剧情不重复扣费/加奖励（对比存档前数值）。
4. **剧情·骰子**：掷骰结果产生但未继续处存档 → 重启读取 → 骰点与结果一致。
5. **单挑**：行动按钮出现后存档 → 重启读取 → 回合数、双方生命/气力/状态、
   行动点一致 → 下一步可正常选择 → 战斗结束进入结算。
6. **覆盖方向**：实验槽被普通档覆盖、普通槽被实验档覆盖，各做一次；覆盖过程中
   用任务管理器结束进程模拟崩溃，重启后确认该槽仍可读取且不丢原档。
7. **删除槽位**：删除含实验附档的槽 → 重新保存到同一槽 → 读取成功。
8. **关闭功能**：关闭随时存档后读取既有原生档，行为与未安装插件一致。

任一项失败请保留该槽的 `.dat`、`.mha`、`.mhduel`、`.mhtx` 与 `.mhtx.bN` 文件
以及 BepInEx 日志。

## 2026-10-22 原生战斗档与恢复输入保护修复（网页端候选）

- 原生 Combat 编号档没有单挑附档时，若也没有“附档必需”标记，不再被当成损坏的实验中途档。新的单挑中途档在双文件核验成功后、清理中断标记之前，持久写入 `.mhduel-required`。读取时若缺少必需 `.mhduel` 会明确拒绝；中断或回退失败仍保留 `.mhduel-pending` 以阻止误读。
