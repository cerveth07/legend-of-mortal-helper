# 活侠·万象录

一个《活侠传 / Legend of Mortal》的整合 Mod。

主要功能：

- **天命控骰（在判定页内，不占面板）**：轮盘旁常驻一个点数输入框 —— 留空即自然掷骰，填数字则按本次判定范围校验后使用；**直接点击选项即选择**（用游戏原生的选中特效：底图/箭头/高亮字/音效）。面板里不再有三态开关。
- **选项后果提示**：把「选完会怎样」写在选项后面（总是）或悬停查看，只列脚本里能直接读到的变化。
- **单挑对白回看**：记录本场/最近一场单挑的实际对白，最多 500 条，不暂停战斗。
- **战斗辅助**：单挑七项（生命、气力、闪避、必定命中、必定先手、造成伤害为零、一击必杀）、群战六项，可分别开关。
- **养成辅助**：练功与锻造炼丹消耗不减、「快速」一次完成一级、无限日常行动点、最高好感。
- **存档扩展**：存档格数 2–999、槽位备注（`F2`）、按最近存档排序（`F3`），以及默认关闭的实验性随时存档。
- **精确恢复（实验）**：记录检查点（基线存档 + 骰子/选项事件）并可回放；播放按「脚本名 + 选项文本 / 判定序号」校验，实机未验证。
- 常见数值编辑：属性（26 项白名单）、物品数量、游戏速度（0.25～5 倍）、解除修炼点数消耗上限。
- 人际关系：好感编辑与心上人指定。

当前源码为 **0.1.1 开发候选**，本轮随时存档验收使用 Steam Build 26073097、Unity 2020.3.49f1、BepInEx 6.0.0-be.692（Mono / x64）。`v0.1.0` 是较早的历史预发布，未包含当前修复；请勿把旧包当成当前源码的验证结果。随时存档的本轮实机结果见 [随时存档验收](docs/ANYTIME-SAVE-ACCEPTANCE.md)；其余辅助功能不据此视为全部通过。精确恢复入口默认隐藏且停用，只有测试者显式配置 `Recovery/ExperimentalEnabled = true` 才可录制与回放；自由场景与 Unity 随机状态尚未完整恢复，仍可能因严格校验失败而中止。

UI 为用户自制，保留原有界面；不能因代码曾位于旧整合项目的 DiceMaster 目录就认定 UI 来自该作者。旧项目另含未获额外许可的第三方功能代码，用户确认新版功能已自行实现、不需要旧版。UI 归属与非 UI 功能代码来源分开记录，MIT 仅适用于有权授权的内容。公开前的来源复核见 [PROVENANCE.md](PROVENANCE.md)，运行依赖见 [THIRD_PARTY.md](THIRD_PARTY.md)，验证范围见 [验证记录](docs/VALIDATION.md)。

## 界面（UI）要点

- **收起/展开**：`Tab` 收起后左侧（可拖动）是竖排「萬象錄」徽章，底部有 `Tab` 提示标签；点击展开。
- **尺寸**：面板最小 **400 × 570**（`scale > 1` 时按比例放大），低于下限会被自动抬回，避免拖成布局撑不住的尺寸。标题栏可拖动，四边/四角可缩放，尺寸与位置会记忆。
- **字体**：正文用系统中文字体（Microsoft YaHei UI），徽章尝试使用楷体（KaiTi，缺失时回退雅黑）；实际效果受系统字体影响。
- **文字布局**：所有说明文字用显式宽度绘制（量多少画多少），控件高度按字号 + 内边距取整，行高固定；不同 DPI 与分辨率仍需回归。
- **自检工具**：配置 `Diagnostics/AutoTour = true` 后启动游戏，mod 会自动切 10 个视图并截图到 `BepInEx/config/mh/`；`Diagnostics/PreviewEditable = true` 可按可编辑宽度绘制三张编辑表（不写入）。详见 [界面状态](docs/UI-STATUS.md)。
- 界面截图：[剧情](docs/shots/story.png) · [战斗](docs/shots/battle-duel.png) · [数值编辑](docs/shots/numeric-edit.png) · [存档](docs/shots/save.png) · [收起徽章](docs/shots/badge-collapsed.png)

## 一、功能与用法

`Tab` 打开/收起面板。界面分七页：**剧情辅助 / 战斗辅助 / 养成辅助 / 数值编辑 / 地图 / 存档设置 / 语言**；最后一页可切换 简体中文 / 繁體中文 / 日本語 / 한국어，设置立即生效并保存（未翻译的长消息回退显示简体原文）。`剧情辅助` 下有「单挑回想」子页，`养成辅助` 下有「人际关系」与「称号」子页。收起后左侧是竖排「萬象錄」徽章，点击展开、可拖动并记忆位置。底部滑杆调界面透明度（40%～100%），窗口四边/四角均可拖拽缩放，标题栏可拖动移动。

### 1. 剧情辅助

| 功能 | 用法 | 默认 | 限制 |
|---|---|---|---|
| **天命控制（控骰）** | 判定页轮盘旁常驻点数输入框：留空即自然掷骰，填数字则本次判定用该点数；**直接点击选项即选择**（走原生选中特效）。面板里不再有模式开关。 | 留空（自然） | 点数按本次判定的 `diceMin`～`diceMax` 校验，越界不扣命运点；重掷仍走原生命运点；动画期间禁止重复提交；判定页始终提供重掷/范围阶段，所以零命运也能直接点选项 |
| **选项后果提示** | 「选项后果提示」三态：`关` / `悬停`（收起面板后悬停选项，弹出后果框）/ `总是`（后果直接写在选项后面，不用悬停）。显示内容由「显示范围」决定。面板底部常驻一行状态：当前剧本、可解析几个选项、其中有几个有内容。 | 悬停 | 只列脚本里能直接读到的调用：条件分支里的、参数是算出来的、注释掉的都不计入；属性/物品名取自游戏自身的数据表；每项最多 16 条效果、6 条去向 |
| **显示范围** | `简洁`：只写属性、人物关系与物品；`完整`：另加解锁条件、剧情标记、任务、天赋与分支去向（分支点 / 后续剧情 / 换场景）。 | 简洁 | 剧透程度不同 |
| **锁住选项的解锁条件** | 被条件挡住的选项（游戏显示「解锁条件：？？？」）悬停时列出**真正的条件与当前值**（绿√/红×），单一属性条件旁有「一键设为 N」：点两次写入该属性并把这一行就地解锁（沿用游戏自己的行监听，选它仍走原来的分支）。 | — | 只读游戏条件表、不调用条件求值函数（避免污染计数与随机数）；含随机、且/或、好感、道具、旗标的条件只显示不改；写入走数值页同一条带中途档记录的通路；`talk+…` 走访问询菜单的选项不支持 |
| **精确恢复（实验，默认停用；入口已移到「存档设置」页）** | 开始记录 → 游玩（记录原始骰子点数与选项点击）→ 保存检查点；从主检查点或上一份历史备份明确选择恢复。回放在完整选项列表稳定后匹配目标，只在原生骰子返回预期点数后确认事件完成。 | 关 | **实机回放尚未验收，默认停用，需显式配置开启**；恢复需二次确认且会覆盖当前未存档进度；无匹配选项会等待至超时，歧义或验证失败会中止；旧版自增序号记录不兼容 |
| **单挑回想**（子页） | 记录本场/最近一场单挑实际调用的对白，最多 500 条，新单挑开始时清空。 | — | 回想不暂停游戏 |

### 2. 战斗辅助

控骰条可按住「基础点数」文字或空白处拖动；松手自动记住位置，输入框与按钮照常操作。

单挑辅助（含总开关）从下一次行动生效，已开始的行动按开始时设置完成。随时存档会记录开场和每次行动的辅助设置；读取时重放这些设置，恢复后沿用当前偏好。

全部默认关闭，单挑与群战分组互不混用。

**单挑（回合制，`Mortal.Combat`）**

| 开关 | 效果 |
|---|---|
| 主角生命不减少 | 阻止战斗扣血与持续伤害；保留剧情直接改值与强制胜负 |
| 单挑无限气力 | 保持行动所需气力，不修改周目内力属性 |
| 主角最高闪避率 | 闪避率拉到上限；不能避开必中特技或剧情结果 |
| 主角必定命中 | 敌方基础闪避失效，主角攻击不会落空（只提高命中） |
| 主角必定先手 | 行动对比判定主角成功、敌方失败：主角先出手，敌方本回合行动失效 |
| 造成伤害为零 | 敌方受到的伤害归零（含持续伤害），主角打不掉敌人血；与「一击必杀」互斥 |
| 敌方受到有效伤害时一击必杀 | 敌方有效受伤时耗尽生命；自动附带必定命中与必定先手 |

**群战（即时战斗，`Mortal.Battle`）**

| 开关 | 效果 |
|---|---|
| 主角生命不减少 | 仍可能硬直；友军与剧情强制退场沿用原生规则 |
| 友军生命不减少 | 独立开关，默认关闭；只保护 Friend 阵营的存活友军，保留回血、受击和剧情退场；包含在群战全部开启/关闭中 |
| 主角气力保持充足 | 作用于群战气力条 |
| 群战技能无冷却 | 保留原生施放限制与演出 |
| 冻结群战剩余时间 | 保持开启时的剩余时间；**靠计时归零获胜的关卡请关闭** |
| 敌方受伤即倒地 | 含友军攻击与持续伤害；保留敌方闪避与剧情无敌，不影响中立与友方 |

### 3. 养成辅助

| 开关 | 效果 | 默认 |
|---|---|---|
| 练功消耗不减 | 练功结束后把武学点数恢复到操作前的值；修炼条件仍须满足 | 关 |
| 快速练功 | 把本次消耗换成「当前级剩余点数」，一次完成一级；升级奖励照常 | 关 |
| 锻造炼丹消耗不减 | 操作结束后把点数与金钱恢复到操作前的值；不解锁研发 | 关 |
| 快速锻造炼丹 | 同上，一次完成当前级 | 关 |
| 无限日常行动点 | 行动点至少为 1 且不减，日期不会因行动用完自动推进 | 关 |
| 最高好感 | 已登场角色维持各自好感上限；不解锁未登场角色 | 关 |

**人际关系**（子页）：好感编辑（仅已登场角色，0～各自上限，应用前复核当前值）；心上人（九位候选 + 自己，写入 `GameStatType.愛人`，不补齐结缘事件）。

**称号**（子页）：列出本档已获得的称号，点击「使用」替换显示，或选择「跟随剧情」。开启「显示全部称号」可选择未获得称号的外观，但不会把它标为已获得。仅在自由活动空闲时修改；选择与已获记录随当前存档保存，新开游戏、读取不同存档互不混用。旧档首次使用只能确认当前原生称号；后续获得的称号开始累积记录。仅改变展示，剧情使用的原生称号数值保持不变；本功能待用户实机验收。

### 4. 数值编辑

| 功能 | 用法 | 限制 |
|---|---|---|
| 属性编辑 | 26 项白名单（金钱/个人贡献/门派资产…拳掌/暗器/刀剑/轻功…），支持筛选；应用前复核对象与当前值 | 商店、菜单、剧情对话/选项、骰子稳定页和单挑行动等待可改；加载、恢复及行动结算期间暂缓 |
| 物品数量 | 按四类（书籍/杂物/贵重品/消耗品）列表选择，支持按名称或物品 ID 筛选 | 默认只列已有物品，开启「显示未持有物品」可设置未持有数量；范围 0～999999。商店内修改会刷新列表并重置待购/待售数量 |
| 游戏速度 | 0.25～5 倍滑杆 + 「恢复 1 倍」 | 只改 `Time.timeScale`，不接管原生暂停/慢动作；插件卸载时还原为 1 |
| 解除修炼点数消耗上限 | 练功面板不再限制单次消耗，按现有武学点数扣减 | 保留修炼条件与升级奖励 |

数值修改与撤销会记录到剧情、单挑恢复日志，读取时按原等待位置恢复修改并保留完整状态核对。剧情内的商店交易尚未纳入重放；在那里修改后，请继续到下一段剧情再保存中途档，面板会提示。群战期间修改的是周目属性，正在进行的战斗如何更新由游戏原生规则决定。

### 5. 地图

显示「崆峒派地图」，默认保持比例完整显示。滚轮缩放、按住拖动查看地名，点击「复位」恢复全图。直接读取游戏自带原图，离线可用；关闭辅助总开关时仍可查看。

### 6. 存档设置

| 功能 | 用法 | 说明 |
|---|---|---|
| 随时存档（实验） | 在本页开启后，使用游戏「系统→储存游戏」的编号槽位；在剧情对话或选项等待处、骰子掷骰前或结果页保存，再从游戏原生读档列表读取；骰子页使用轮盘旁的「存档」按钮。**单挑**在行动按钮出现时也可以存，但写入的是「这场战斗开头」的状态（与游戏自己的战前自动档同义）：读档直接重开这场战斗，不需要重放；旧版本写出的带 `.mhduel` 精确档仍可按原来的重放方式读取 | 剧情档附带 `.mha` 和 `.mha-required`，单挑档附带 `.mhduel` 和 `.mhduel-required`；这些文件都需要与同槽 `.dat` 一起备份和移动。群战、轮盘动画、单挑结算中暂不支持；读取会重放并核验，失败会中止并保留保护锁，需重新读取有效原生档 |
| 通关故事栏位 | 保留原生12个书脊，存满后按12→18→24→30追加；横向拖动或滚轮查看 | 复用原生书脊、悬停和覆盖确认；可在本页调整扩展上限。降低上限仍显示已有高编号故事，不删除记录；待用户实测 |
| 存档格数 | 输入 2～999 后点「保存格数」，重新打开存档/读档界面生效；点「恢复默认」用游戏原值 | 只改变列表建多少个槽位，**不改动任何存档文件** |
| 存档备注 | 在游戏存档列表选中槽位后按 `F2`，面板跳到本页编辑；备注显示在槽位标题下方 `〔备注〕…` | 存配置目录 `cerveth.mortal.helper.slots.txt`（旧版放在存档目录，本版不改动存档目录） |
| 按最近存档排序 | `F3` 切换 | 仅重排读档列表行顺序，槽位编号与文件不变 |

剧情中途档的读取方式是**重放**：游戏本身只记录「从哪段脚本重来」（原生存档点也都放在脚本入口），所以读取时会从本段脚本开头重跑一遍；期间用黑屏遮挡、以 15 倍速推进，只在命中记录的事件上推进，到点后做完整状态核对、恢复你的游戏速度并交还操作。读档前会先把本次会话的已读记录落盘，避免刚看过的台词又变回未读。日志里 `[Anytime] replay start …` / `[Anytime] replay done X.Xs events=N` 两行可用来核对耗时。

随时存档与「精确恢复」的检查点是两套独立功能。前者写入游戏编号槽位，并为中途状态保存配套记录；后者使用配置目录中的 `.mhr`，入口默认隐藏，仅供显式开启实验恢复或诊断巡视后的高级测试。随时存档已完成本轮剧情对话、选项、骰子等待页与单挑行动点的真实游戏保存→退出→读取验收；具体场景、构建和支持范围见 [随时存档验收](docs/ANYTIME-SAVE-ACCEPTANCE.md)，不代表所有剧本和战斗均已验证。

## 二、安装

推荐从 [Releases](../../releases) 下载 **`MortalHelper-Setup.exe` 便携安装器**（不要下载 Source code）。本轮0.1.1候选已在本地构建，尚未发布。适用于 Windows 10 / 11 x64。

1. 完全退出游戏，备份存档。
2. 双击安装器，自动识别 Steam 游戏目录；未找到时点击「选择…」，选择游戏的 `Mortal.exe`。
3. 点击「安装 / 更新」。首次安装会离线安装所需加载器，已有兼容加载器则保留原样。
4. 从 Steam 启动游戏，按 `Tab` 打开万象录。

以后用同一安装器更新或卸载。安装器不常驻，不注册服务，无需管理员权限，用完可删除；以后需要时重新下载即可。卸载保留游戏存档和设置；共用或已修改的加载器保留。未做代码签名，下载页提供 `.exe.sha256` 校验文件。

仍提供 **`mortal-helper-0.1.1-plugin.zip` 仅插件包**，供已经安装 BepInEx 6 Mono x64 的用户手动更新。离线安装器附带固定验收版本加载器的许可证、署名和对应源码；见 [安装器说明](installer/README.md) 与 [第三方材料](installer/third-party/THIRD-PARTY-NOTICES.md)。

制作自建包：

```bash
python build.py --game "<游戏目录>" --loader "<BepInEx core 目录>" --compiler "<csc.dll>" --test
python tools/package.py --plugin artifacts/MortalHelper.dll --out dist/0.1.1 --version 0.1.1
python tools/build_installer.py --plugin artifacts/MortalHelper.dll --loader-zip "<官方be692归档>" --out dist/MortalHelper-Setup.exe --test
```

打包器拒绝过期源码、未通过测试或包含开发探测的产物，并拒绝覆盖现有包目录。

如果你更愿意自己装：
1. **完全退出游戏**，把存档目录整体备份（通常为 `%USERPROFILE%\AppData\LocalLow\Obb Studio\Mortal\<SteamID>`）。
2. 安装 [BepInEx 6.0.0-be.692](https://builds.bepinex.dev/projects/bepinex_be/692/BepInEx-Unity.Mono-win-x64-6.0.0-be.692%2B851521c.zip)（Unity Mono x64）到游戏目录：解压后应存在 `winhttp.dll`、`doorstop_config.ini`、`.doorstop_version`、`BepInEx\`。
3. 把 `MortalHelper.dll` 放进 `BepInEx\plugins\`（子目录也可以，例如 `BepInEx\plugins\cerveth.mortal.helper\`）。
4. 从 Steam 启动游戏，等待加载完成后按 `Tab`。

正确层级：

## 三、备份、升级与卸载

- **备份**：退出游戏后复制完整存档目录（含随时存档生成的 `.mha`、`.mha-required`、`.mhduel`、`.mhduel-required`）、`BepInEx\config`（含本插件的 `cerveth.mortal.helper.cfg`、`*.choices.txt`、`*.slots.txt`、`mhr\`）、以及 `BepInEx\plugins` 下的插件。
- **升级**：替换 `MortalHelper.dll` 即可；配置与记录文件保留。
- **卸载**：使用便携安装器的「卸载万象录」；手动安装用户只移走本插件 `MortalHelper.dll`；共用加载器和其他插件应保留。已制作的剧情或单挑中途档依赖插件重放，卸载后应从普通原生存档读取。关闭开关不会删除已有的中途档附加记录，也不会撤销已写入的数值或备注。

## 五、已知限制与未实现

- **未实现**：强制事件 / 取消待执行事件与任务（旧版通过替换 Lua 待执行队列实现，会跳过剧情前置条件）；「自动选择固定分支」；旧版 `.loms` / `.duel` 附加档的迁移读取。（便携安装器已实现，见[安装](installer/README.md)。）
- **恢复功能仍是实验**：记录与播放均已接线，首次保存可写入并验证主检查点，覆盖写入后才产生历史备份。播放等待选项菜单稳定、校验原始骰点，但**尚未完成原生游戏的完整回放验收**；基线可能落后于真实剧情位置，`FreeRandomState` 也不会恢复。恢复前请正常存档，且不要把 .mhr 当作原生存档。新的精确校验使用 `MHRSTATE3` 全状态指纹（忽略原生 JSON 顶层 TimeTick）；旧摘要版本的记录文件不会被删除，但不能再启动实验重放。任务状态若无法可靠读取会拒绝保存/恢复，避免误报成功。恢复失败后需从游戏原生存档重新读档解除锁定。
- **随时存档仍是实验**：只在剧情对话/选项、骰子掷骰前/结果页稳定等待和单挑行动点开放保存。骰子页点击轮盘旁的「存档」；掷骰动画和已经提交的操作期间不开放保存。恢复会还原历史点数、实际选项、点数范围与命运消耗，恢复后沿用当前控骰设置。单挑辅助的开场与逐行动设置随档记录，可在开启辅助时保存，读档不会改写当前偏好；修改辅助（含总开关）从下一次行动生效。未知随机调用、脚本变量无法核验时会拒绝保存。读取时若附档与原生档不匹配：附档仍标记为必需件（`-required` 存在）则视为不可判定并拒绝；标记已不在则把附档保留为 `.stale` 并按原生档载入，界面会说明当前处于原生检查点而不是精确恢复点；缺少必需附档时拒绝。重放超时和状态不一致时会锁定操作并回到标题，需从可用的原生档重新读取。本轮已验证的实际场景、重启往返与故障保护见 [随时存档验收](docs/ANYTIME-SAVE-ACCEPTANCE.md)，不代表所有剧本和战斗穷尽验证。
- **验证到什么程度**（详见 [验证记录](docs/VALIDATION.md)）：

  | 已验证 | 未验证 |
  |---|---|
  | 指定点数注入（判定范围 0～99 时注入 37 → 掷出 37） | 重放注入全链路 |
  | 存档备注写入与回读 | 特殊技能、剧情强制结果下的战斗辅助边界 |
  | 游戏速度、存档格数配置生效 | 养成辅助各开关 |
  | 真实剧本上的选项提示与后果解析 | `F2` / `F3` 交互 |
  | 随时存档的剧情台词/选择、骰子等待页与单挑行动点原生槽位存读、再次存读及故障保护 | 全部剧本、战斗、轮盘和辅助组合的穷尽回归 |
  | 基线存档可无损载回、载入后可进剧情 | 数值编辑实际落值 |
- **存档安全**：不要加载来源不明的存档；本插件的 `mhr` 记录只用于自身恢复，不替代原生存档。
- **`Diagnostics/SelfTest` 是开发用探测**：只在 `--diagnostics` 构建里存在，开启后仅记录一次当前场景与 API 状态，不读档、不自动推进、不写进度。
- **来源说明**：用户已确认 UI 为本人自制；旧整合项目中的第三方功能代码不因 UI 作者归属而获得许可，见 [来源说明](PROVENANCE.md)。

本次修复分支另新增了对首次存储、0 点骰子、非法选项以及重放预读的合同断言；新增测试尚不能代替需要本机游戏与加载器的交互验收。

## 六、构建与测试（开发）

需要 Windows 或 WSL、Python 3、.NET 8 运行时、Roslyn 4.12 `csc.dll`、本机游戏，以及 BepInEx 6.0.0-be.692 Mono 的 `core` 目录。脚本不下载依赖，也不安装到游戏。

```powershell
python build.py --game "D:\steam\steamapps\common\LegendOfMortal" `
                --loader "本地\BepInEx\core" `
                --compiler "本地\Roslyn\tasks\netcore\bincore\csc.dll" --test
```

- 产物输出到被 Git 忽略的 `artifacts/`，构建记录含源码与测试文件的 SHA-256，不含游戏程序集，也不含本机依赖清单。
- `python -m unittest discover -s tests -p test_package.py`：检查打包路径、摘要、新旧版本与校验和边界。
- `tools/check_source.py`：检查源码/文档目录没有游戏或旧插件二进制、旧命名空间。
- `tools/provenance_scan.py`：与旧仓库源码做 token shingle 与最长公共片段比对（启发式，非法律结论）。
- 离线断言：`tests/Contracts.cs`，只用人工数据与临时目录，不读取玩家存档；实际断言数以运行输出的 `PASS:` 行为准（历史各轮的计数会随断言增删变化，见[验证记录](docs/VALIDATION.md)），本文件不写死数字。
- 无游戏依赖的测试：安装 .NET 8 SDK 后运行 `python build.py --test-only`。可在不提供游戏程序集的环境执行这组测试和源码清单检查；完整插件构建需要本机游戏依赖。
- WSL 可传 `--dotnet "/mnt/c/Program Files/dotnet/dotnet.exe"` 使用 Windows 运行时编译；运行时本身不包含 SDK，因此 `--test-only` 需要另有 SDK。`--test` 可用本地 Roslyn 与 .NET Framework 引用运行，无需 SDK。
