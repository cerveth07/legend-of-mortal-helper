# 跨版本剧情中途档恢复（1.1.0）

## 玩家可见行为

版本号变化不再直接拒绝剧情中途档。读档先检查原生文件与附档配对、格式及完整性，再检查旧字段能否在当前版本表达，最后重放并核对等待点、Lua 变量和游戏状态。跨版本恢复前备份原槽位，成功后建议另存新槽位。

新增的剧情记录格式为 v5；仍读取 v3/v4。新记录额外携带本段 Lua 源码和校验值，精确恢复时只替换匹配的本段脚本，其他脚本不受影响。旧记录没有源码时，仍尝试当前脚本并严格核对执行结果。

存档设置新增“从本段开头恢复所选档”，需要在界面再次确认。该操作使用记录的段落起点状态，按当前剧本重新开始，段内选择需要重走；不冒充精确恢复。缺少附档时在改变当前槽位或玩家状态之前拒绝。原档保留且先备份。

## 完整性与兼容规则

- 原生 `.dat`、`.mha` 和必需标记保持配对，沿用先备份、写入事务日志、写后核验、提交或回退的机制；不会把“备份缺失”解释为“原槽位为空”。
- 无论版本号是否变化，旧字段缺失、字段类型不符、数值溢出、非空字段变 null 均拒绝静默加载。
- 跨版本核对按属性、人物关系、旗标、天赋、书籍、物品的稳定编号对齐，允许顺序调整。新字段和新编号必须保持原生加载后的起点默认状态，不能在恢复时无声漂移。
- 原生旗标集合可能重复引用同一资源；相同编号且状态完全一致的别名允许归并，冲突值拒绝。运行时还核对旗标实例映射，重名的不同资源不能猜测。
- 版本号和保存时间不作为游戏状态差异；仅当旧档没有 StoryLogs 时，允许新引入的回想展示记录不参与等值比较。旧档原本有的回想仍检查。随机状态、已有剧情和数值不会因此被忽略。
- 重放保留内存中的剧情修改以核验最终结果，但拦截原生持久写入、删档和成就接口，避免剧情快进时重复写自动档或重复触发外部效果。验证完成后恢复正常保存。
- 精确恢复失败会退出恢复流程并请求返回标题；不会自动把半恢复状态交给玩家。仍保留加载超时和输入锁释放保护。

## 备份位置

插件配置目录下 `checkpoint-backups/<槽位>-<内容标识>/`，包含原生档、剧情附档和必需标记（存在时）。每件备份校验后才继续；重复恢复复用相同内容的备份，不覆盖原件。

## 边界

不能承诺未知大版本一定恢复原句：游戏删掉或改变已有字段/编号、原生接口改变、脚本依赖的资源和引擎行为变化仍可能需要专门适配。保存一段 Lua 源码不等于保存整个旧游戏。入口恢复也需要可表达的旧起点状态，不能绕过数据损坏或未知字段迁移。

本轮扩大的是剧情中途档的跨版本能力。旧 `.mhduel` 精确单挑档仍保留版本限制；当前单挑存档仍是战斗开头，没有宣称任意战斗回合跨版本恢复。

## 对照研究与设计来源

参考 [LOMAssistant v3.0.8](https://github.com/kevinnie2003/LOMAssistant/releases/tag/v3.0.8) 对存档格式、游戏代码、经过的剧本分别校验的思路，以及重放时抑制持久副作用的做法。本实现独立编写，没有复制其源码。该项目会拒绝已改动的经过剧本；本项目新档另外保存本段源码，并以最终状态严格核对作为恢复成功条件。未照搬其白名单或宣称已经具备其方法体契约指纹检查。

历史更新说明表明，大更新不只是增加文字：1.0.5000.0 新增路线和支线；1.0.6000.0 增加路线、战斗能力、难度及分支条件调整；本机 1.0.6001.0 的创建快照接口和回想数据也有变化。因此不能只删除版本号检查。
