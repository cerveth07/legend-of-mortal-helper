# 界面（UI）状态与遗留问题

本文件记录面板界面在最近一轮改造后的实际状态、验证方式，以及**仍然存在**的问题。
配套截图在 [`docs/shots`](shots)。

最后复核：2026-10-20。以下实拍矩阵来自 2026-10-19 的历史记录，未重新验证本轮 0.1.1 修复。仓库仅保留五张示例图，完整矩阵证据不在仓库内。

---

## 一、本轮做了什么

### 1. 根除"挤压 / 显示不全"的三层原因

| 层 | 现象 | 根因 | 处理 |
|---|---|---|---|
| 布局拓扑 | 行叠行、显示一半、位置错乱，点击后更明显 | 面板调用了 `GUILayoutUtility.GetLastRect()`，而 IMGUI 的 Layout / Repaint 两遍之间**控件数量不一致**，取位置直接抛 `ArgumentException: Getting control N's position in a group with only M controls`，整帧布局组被打断 | 删除全部 `GetLastRect`（源码中为 0 处）；所有"点击后增减控件"的动作改为 `Defer(...)`，统一在 `Plugin.Update`（OnGUI 之外）执行；确认类操作改为**同一个按钮点两次**，控件数恒定；搜索框输入写缓冲，下一帧才应用过滤 |
| 控件高度 | 按钮被压成一条、"保存格数"只剩半行字、输入框里数字被竖切 | 行高按 `22/24 × scale` 计算，0.85 缩放后只有 19–20px，而字号 14px + 内边距 5+5 → 文字垂直溢出 | `RowH = max(24, round(27 × scale))`；输入框/按钮内边距 5,5 → 3,3；行最小高取整；徽章/标题字号由可用高度反推 |
| 文本宽度 | 说明文字最后一行被下一个控件压住；标点单独成行 | 高度用 `CalcHeight(估算宽度)` 预留，实际绘制宽度由 IMGUI 决定，两者差 1–2px 就会多出一行 | 所有说明文字改为**显式宽度**：`GUILayout.Label(text, style, GUILayout.Width(ContentWidth()))`，量多少画多少；开关行标签同样改为显式宽度 |

另外把三张编辑表（属性 / 物品 / 好感）从"先点条目、再在下方输入"改为**列表内直接编辑**，列宽改为按内容宽度比例分配，名字列 `ExpandWidth` 吸收余量，所以**变宽只会变松，不会变挤**。

### 2. Tab 收起徽章（缩小版 UI）

- 徽章由 52×150 放大到 **58×168**；底部 `Tab` 标签区按 `min(22×scale, 高度×17%)` 计算，字号由标签区高度反推（11–20px），文字用 `Overflow` 裁切策略 → 不再被切。
- 竖排「萬象錄」字号同样由可用高度反推（11–24px）。

### 3. 小标题竖线与文字对齐（本轮补）

原先竖线与标题是两个独立控件：竖线从行顶画 18px，文字按行盒顶对齐，实测在 scale 1 下竖线比字形高 3px、且长 2px。现在两者共用一行矩形（高度取文字测量高度），竖线按字形墨迹高度缩短并按光学中心下移 3px，实拍复测竖线中心与文字中心一致（329.5 / 329.5）。

### 4. 收起徽章的底部轴帽（本轮补）

徽章的实现里顶部轴帽（`ScrollRoll`）有绘制调用，底部只有一条细横线和 `Tab` 标签；而布局计算本来就为底部轴帽留了 `inset + rollH` 的空间，说明绘制调用在改版时被漏掉。现已补上，实拍确认上下对称。

### 5. 语义与层级（本轮）

- 子页签改为「剧情 / 回想」「养成 / 人际」「单挑 / 群战」，不再与页签同名；
- 子页签从整条棕色块改为**文字 + 强调色下划线**；战斗页「全部开启 / 全部关闭」改为右下角小号描边按钮，与视图切换区分；
- 「上次操作」行改为**固定高度占位**，出现/消失不再让整页内容跳动；
- 宽面板改为**固定内容列居中**（720×scale 上限 + 左右对称留白）；
- 数值/物品应用成功后该行短暂高亮 300ms；
- 文案统一：「减少 / 增加」「删除」「清空」；滚动条加宽到 7–8px，悬停变亮。

### 6. 尺寸下限（防止拖进布局撑不住的区间）

- 最小宽度 **420**、最小高度 **600**（`scale > 1` 时按比例放大；在 1600×900、scale=0.85 下即 420×600）。
- 600 是算出来的：最高的战斗页（7 行 × 约 51px + 抬头 / 页签 / 底栏）在此高度刚好完整显示。
- 启动与拖动都会走同一个 `Clamp()`，即使是旧的过小配置也会被自愈到下限。

## 二、怎么验证的

面板内自带一次性自检巡视（配置 `Diagnostics/AutoTour`，默认 `false`）：

1. 置 `AutoTour = true` 后启动游戏；
2. mod 自动打开面板 → 逐个切到 10 个视图 → 每个视图用 `ScreenCapture` 存图到 `BepInEx/config/mh/tour-<n>-<view>.png` → 自动关闭；
3. 结束时会把 `AutoTour` 与 `PreviewEditable` 复位为 `false` 并保存配置。

`Diagnostics/PreviewEditable = true` 时，属性 / 物品 / 好感三表会按**可编辑宽度**绘制（但不写入），用于在标题界面等不可编辑场景下核对布局。

## 三、仍然存在的问题（未解决 / 已知限制）

1. **尺寸下限是硬约束**：面板宽不能小于 420、高不能小于 600（scale=0.85 时）。
   代价是不能再拖成很小的窗口；若要更小，需要改成"标签在上、控件在下"的堆叠布局，那是另一次改版。
2. **尺寸覆盖仍不完整**：已有 1600×900（scale 0.85）、1920×1080 下 640×600 与 1000×780 两组实拍（`BepInEx/config/mh/tour-*.png`）；1.35 缩放未实拍，不同 DPI 下仍可能出现未预料的换行。
3. ~~**宽面板会"空"**~~：已加内容宽度上限（`720 × scale`），宽窗口多出来的空间留作右侧留白，开关不再被拉离文字。
4. ~~**右侧 5px 滚动条槽常驻**~~：已改为仅在内容溢出时显示滚动条，不再常画金色细线。
5. **部分单行文本仍会硬裁**：属性名 / 物品名已改为按列宽省略号（`Fit()`）；其它单行列（如范围、数量）本来就短，未加省略号。
6. **精确恢复（实验）的播放链路仍未实机验证**：界面部分已核对，回放/校验链路需要在真实存档上跑一遍。
7. **数值编辑的"可编辑"状态是用只读预览核对的**：布局与真实可编辑态一致，但"落值 → 存档保留"这条链路本轮没有重新跑。
8. **英文/数字混排与中文字体的度量差异**：说明文字换行以 CJK 为主，长英文串（例如 JSON 键名）可能比估算宽，导致提前换行。

## 四、相关配置键

| 键 | 默认 | 作用 |
|---|---|---|
`Diagnostics/LayoutProbe` 已移除，不再是有效配置键。

| `Diagnostics/AutoTour` | `false` | 一次性自检巡视：切 10 个视图并截图 |
| `Diagnostics/PreviewEditable` | `false` | 只读预览：按可编辑宽度绘制三张编辑表，不写入 |
| `Window/Width`、`Window/Height` | — | 面板尺寸，低于下限会被 `Clamp()` 抬回 |
