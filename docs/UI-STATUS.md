# 界面布局与截图验证状态

更新：2026-10-21。本轮针对文字裁切与横向溢出统一布局预算，保留原有羊皮纸配色、自绘边框、卷轴装饰、开关、下划线子页签与竖排「萬象錄」徽章。

## 本轮布局调整

- **统一可用宽度**：先从面板实际宽度扣除窗口内边距得到 viewport；宽面板的内容列设上限并居中。正文 body 再从 viewport 扣除滚动条及其水平 margin，所有说明、编辑行和列宽使用同一 body 宽度。
- **滚动条只预留一次**：短页和长页均预留竖向滚动条，避免内容变长或 Layout/Repaint 切换时宽度跳变。不能再用额外的固定百分比重复扣减。
- **消除隐含横向占位**：正文标签、按钮、输入框等参与行宽预算的控件，其左右 margin 归零，间隔由行布局显式安排；文字标签的 padding 归零。按钮保留其自身必要的内边距，不宣称所有控件的 padding 都经过逐项测量。
- **主次导航分别适配**：五个主页签按实际文字测量决定列数，每个 slot 固定等宽，放不下时换行；子页签及四类物品导航按 body 宽度分配槽位，避免固定宽度总和超出窄面板。
- **编辑行支持两种结构**：属性、物品和好感在窄面板分为两行，第一行名称与当前值/范围，第二行输入与应用；宽面板使用一行布局。输入示例、数值范围和应用按钮按实际样式测量预留宽度，再分配名称剩余宽度。
- **完整名称换行**：属性、物品与人物名称保留完整文本，由列宽和换行承担长名称，不再依赖省略号掩盖溢出。
- **速度显示独立预留**：先测量倍率文字，再从正文宽度中扣除倍率与间隔分配滑杆，避免滑杆把倍率挤出内容列。

这些是代码层面的布局规则；其显示效果仍以当前构建的真实截图为准。

## 巡视覆盖与限制

当前 AutoTour 共 **13 个视图**：剧情、恢复展开、单挑回想、单挑、群战、养成、人际关系、数值页四类物品、存档和收起徽章。

普通长页按 **0 / 300 / 600 / …** 滚动，直到到达实际钳制末尾。异常长页在 3300 后补拍末尾，并在日志中明确中间内容未穷尽。数值页各分类连续拍到 **2400**，再取后段中点与末尾；较短页面会提前结束。这覆盖属性区域、分类导航与不同位置的物品行，但**不逐行穷尽全部物品**。

每次改变视图/滚动后至少等待 0.5 秒再截图，截图后至少保持 0.5 秒再改变布局，避免异步截图捕获到下一页。全过程在后台运行，不抢焦点、不模拟鼠标键盘、不点击业务按钮。恢复展开仅用于查看控件布局，不改变实验恢复开关，也不启动记录、恢复或写入游戏进度。

这是标题场景中的只读布局预览。角色/物品/属性能否显示，取决于当时游戏进程已加载的数据；缺失数据的提示也属于截图结果。后台实拍能核对文字、列宽、间距和滚动位置，不能证明真实存档场景的数据写入、心上人应用、战斗效果或完整剧情恢复成功。

## 验证边界
- 其他 scale、DPI、系统字体和极长动态文本尚未穷尽；切勿用当前单一屏幕分辨率推定所有环境无裁切。
- 游戏内实际读档后的交互、数值写入及存档保留，需要另做功能验证；本文件只记录布局检查。
