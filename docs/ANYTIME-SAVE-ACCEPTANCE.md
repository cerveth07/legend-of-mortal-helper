# 随时存档验证范围

随时存档默认关闭，仍为实验功能。以下记录区分本次 1.1.0 验证与历史验证；本地候选构建曾使用 1.1.1 编号，正式发布统一为 1.1.0。

## v1.1.0 验证（2026-10-28）

实际游戏为 `release_1.0.6001.0`（Build 26237817）。测试使用存档副本，在后台完成；玩家原始目录 370 个文件的集合和内容保持不变。正式 1.1.0 发布构建已重跑剧情 003、骰子 022 和单挑开场 004 的读取、另存及重读，17 项检查、0 失败。

- 旧 `release_1.0.6000.5` 的 043 剧情/骰子档完整重放 85 个事件，Lua 变量、原有游戏状态和目标等待点核对通过；另存 v5 档后重读通过。
- 剧情 017、003，骰子 013、022，以及单挑开场 028、004 均完成读取、另存和重新读取。骰子阶段、点数、范围和命运状态核对通过；单挑两次均到达玩家行动点。
- 单挑 028 首次自动测试遗漏开场对白确认而超时；追踪定位到原生 `WaitNextInput` 后补上确认输入，存读通过。没有跳过战斗协程或强制设置成功状态。
- v5 附档包含实际脚本源码；归档选择器对模拟变化的当前脚本返回归档文本，其他剧本不被替换。这不等于验证未来真实更新的所有资源变化。
- 故意设置不匹配目标，恢复被拒绝并返回标题。明确选择段落起点恢复后，可进入剧情并另存新档；缺少附档的请求不改变当前槽位。
- 门派好感、六项天赋的读取/修改/还原，以及普通原生档、覆盖保存清除备注通过检查。
- 599 项契约、258 项群战、32 项称号、86 项编辑、21 项备注、49 项提示检查及 42 项 Python 检查通过；20 项本机游戏元数据契约检查通过。

后台运行不替代界面视觉验收，未穷尽所有剧本、战斗和辅助开关组合。旧 `.mhduel` 精确档的版本限制仍保留；当前单挑保存的是本场战斗开头。未知游戏大版本仍可能需要适配。详细规则见 [跨版本存档说明](CROSS-VERSION-SAVES.md)。

## 已有实机证据

此前的游戏构建在隔离存档环境中，通过实际存读档界面完成下列往返：

| 场景 | 已验证的结果 |
|---|---|
| 剧情台词和选项 | 保存、完全退出、重新启动、读取后回到目标等待位置；状态校验通过，并能继续推进、再次保存和读取。 |
| 骰子等待页 | 掷骰前、普通结果、重掷、范围变化和直接选择分支均曾完成冷启动读取及后续推进；动画期间拒绝存档。 |
| 原生存档边界 | 关闭实验功能后，原生保存与冷启动读取正常；实验附档缺失或损坏时明确拒绝错误配对，随后仍能读取有效原生档。 |
| 旧单挑精确档 | 旧方案曾完成首回合与多行动冷启动读取、再次保存及战斗结束。v1.0.0 的新单挑存档改为“战斗开头”，此项历史结果不能作为新方案的验收。 |

以上证据对应此前各自的构建，不等于 v1.0.0 发布包已经完成相同的实机闭环。游戏版本基线为 `release_1.0.6000.5`、Steam Build `26073097`、Unity `2020.3.49f1`、BepInEx `6.0.0-be.692`。原始测试日志、游戏资产和玩家存档不随源码分发。

## 当前版本边界

- 剧情仅在可建立恢复起点的台词、选项及骰子稳定等待位置开放；未知或无法核验的 Lua 状态、动画、群战和恢复过程中拒绝保存。
- 单挑只保存本场战斗开头，读取后从战斗开头重来，不能恢复到保存时的行动回合。旧 `.mhduel` 精确档保留兼容读取路径。
- 实验档依赖同槽的原生 `.dat` 与附档或标记；复制、移动、备份时须保持配对。缺少必需件或校验失败时不能当作恢复成功。
- 本次 v1.1.0 已完成上述后台存读抽查；所有剧本、战斗和辅助开关组合仍未穷尽测试。

如果恢复失败，请读取已确认有效的普通原生档或恢复完整备份；不要反复覆盖故障槽位。
