# 实现进度与下一步

这是进行中的工程记录。不得把第一批源码完成等同于用户要求的三个阶段全部完成。

## 已实现

- 独立目录与插件入口；不引用旧插件二进制。
- 交互会话：关闭、接收输入、已提交、结果完成；世代标识阻止陈旧 UI 回调；显式再武装避免重复点击。
- 原生轮盘 UI 与范围校验、直接选择、重掷前验证、原生扣点；未进行实际 UI 验收。
- 受限 Lua 词法分析与直接效果提示；未知控制流停止，重复标识省略，不执行脚本预测结果。
- 独立配置、可移动缩放面板、单挑辅助、回想、属性与好感编辑。
- 物品数量编辑：`ItemDatabase` 四类物品（书籍/杂物/贵重品/消耗品），本地化名称取自 `LocalizationManager`，应用前复核当前数量；默认只列已有物品，勾选后才显示 0 数量条目（等同于直接生成）；与属性、好感一样只在自由活动空闲时开放。
- 游戏速度：0.25～5 倍滑杆，写入 `Time.timeScale` 并保存配置；只在数值变化时应用，避免和原生暂停/慢动作互相覆盖；插件卸载时还原为 1 倍。
- 天命控制三态：`Mode` 0 自然 / 1 指定点数 / 2 直接选项；点数输入仅在模式 1 生效，选项点击仅在模式 2 生效；基础点数默认 50。
- 养成辅助：`无限日常行动点`（`PositionController.HasActionPoint` 放行 + `GameStatType.行動次數` 维持 ≥1）、`最高好感`（`RelationshipStat.SetActive` 补满 + 自由活动维持上限）、`练功消耗不减`（`MartialPanel.HandleLearnNextItem` 前后暂存/恢复 `_martialPoint`）、`锻造炼丹消耗不减`（`UpgradePanel.HandleUpgradeNextItem` 前后恢复 `_pointData`/`_moneyData`）。「快速练功 / 快速锻造炼丹」尚未接入。
- 心上人：十项候选写入 `GameStatType.愛人`（值取 `RelationshipStatType` 编号）；未实机验证。
- 快速练功 / 快速锻造炼丹：在 `Book.Learn` / `UpgradeItemData.Upgrade` 前缀里把本次消耗替换为当前级剩余点数，动画与升级奖励仍走原生。
- 物品选取路径：`ItemStatPanel.OnItemSelected` 记录游戏物品面板里选中的物品，数值编辑页可直接编辑该物品；读档时清空记录。
- 解除修炼点数消耗上限：`MartialPanel.StartHandleUpgarde` 前缀把消耗夹到当前可用武学点数，`CanUseLearnButton` 放行、`UpdateMartialPointInfo` 显示「不限」。\n- 检查点提醒：`MissionManagerData.AddFlag/SetFlag` 后读 `GetFlag(name).State`，写入「上次操作」。\n- 精确恢复（仅记录）：`StoryRecovery` 用 `SaveSystem.GetCurrentSaveData()` 的 JSON 作基线，记录骰子结果与选项点击，经 `Archive.Encode` 写成配置目录 `mhr\\slot-00N.mhr`；播放侧已写（`StoryReplay`：JsonUtility 解析基线 → 私有 `ExecuteLoadGameData` → 按序注入骰子/选项 → 停点比对摘要，不一致即中止），但**尚未实机验证**，且基线取的是当前内存存档数据，可能落后于实际剧情位置。\n- 存档设置：格数在 `SaveGamePanel`/`LoadGamePanel.CreateSlot` 前缀里改 `_slotCount`；备注存配置目录的纯文本并在 `SetupText` 后追加到槽位标题，`SelectButton` 记录当前槽位、F2 打开编辑器；排序在 `LoadGamePanel.UpdateSlot` 后按 `GameSave.TimeTick` 重排子节点，F3 切换。以上均未实机验证，改格数前请备份存档。\n- 分支记录：`NormalOptionButton` 上挂 `BranchMarker`，显示〔已走〕/〔未记录〕并在点击时记录；键为「脚本名 + 选项文本」，保存在配置目录的纯文本文件；面板可清空并列出最近记录。高级工具（检查点提醒、强制事件）仍未接入。
- 界面：透明度 40%～100%；四边/角落拖拽缩放（原始鼠标轮询 + 高亮边）；标题栏拖动。
- 群战辅助（`Mortal.Battle`，全部默认关闭）：生命 `Character.TakeDamage` 前缀、气力 `CharacterMana.Modify` 补满、技能 `SkillButton.CanProcess` 放行、剩余时间 `GameLevelManager._currentSessionTime` 维持在最大值、敌方受伤即倒地。玩家/敌人用 `Character._entity.CurrentType` 区分，避免误伤友军与中立单位。四个补丁目标在本机启动日志中解析成功，但**战斗内的实际效果尚未验证**。
- 固定字段 `.mhr` 格式；文件预算、严格长度、事件枚举与有限数值检查，截断/损坏拒绝；单文件写入和显式备份读取；原子替换不可用时回退为复制，且损坏主档不会被提升为备份。
- 录制状态与恢复状态：基线、完成事件、等待停点；嵌套交互或内部随机暂不支持时使恢复链失效；恢复顺序/校验失败后保持操作锁。
- 恢复控制器：`IReplayHost` 定义游戏侧契约（客户端标识、加载原生基线、状态摘要、中止），`RecoveryController` 独占“预检 → 加载基线 → 重放 → 校验 → 空闲”的时序；停点交互交给玩家；任何失败只回调一次中止并锁住操作，需显式确认才解锁。该层只通过离线合同测试验证，Unity 适配仍未实现。

## 第二阶段：恢复适配尚未完成

`RecordingSession`、`ReplayCursor`、`RecoveryController` 和文件格式是可执行的底层组件，还没有接入 Unity 中的剧情/单挑恢复：`IReplayHost` 目前只有测试里的假实现。没有新恢复按钮，没有写原生存档或尝试加载旧附加档。

剧情适配需要建立：

- 何时能取得包含剧情基线与 Lua 必需状态的完整检查点；捕获失败应禁用当前链。
- 对话、普通/计时选择、随机、轮盘、命运分配等交互的开始/完成语义；嵌套调用与未知面板应明确处理，不能丢事件。
- 自有状态摘要，排除时间戳等易变项但覆盖影响后续剧情的状态。
- 加载原生基线、进入正确脚本、自动重放、到达停点并验收的一整条链。
- 失败、中止和跨版本拒绝策略，不以继续运行掩盖错位。

单挑适配需要建立：

- 双方稳定行动点、开局基线、玩家动作和随机调用的完整捕获。
- 临时效果、回合阶段、剧情强制结果、UI 和随机状态的一致性验证。
- 开启辅助或手动修改后明确失效；群战现场不能当作单挑支持范围。

旧存档不默认兼容。迁移方案须在备份周目上实测后再写入面向玩家的说明。

## 人工验收清单

使用隔离测试环境和备份周目，不覆盖正在使用的旧整合版。

1. 插件初始化无异常；配置文件单独生成；有旧插件时清楚报冲突。（2026-10-19 已实机验证三项）
2. Tab、鼠标展开收起、拖动缩放、不同分辨率与中文字体可用。（2026-10-19 第二轮：Tab 展开与收起两个方向都由插件日志确认，中文字体已验；尺寸自适应已改但需肉眼看一次；拖动缩放仍待验）
3. 轮盘自然点数、上下界、非法输入、选项点击、动画连点、关闭重开、按键冲突。
4. 无效输入不扣命运点；合法重掷只扣原生应扣次数；直接选项不被旧点数设置阻塞。
5. 已知提示正确，未知提示省略；切换脚本不沿用旧提示；关闭总开关后恢复正常玩法。
6. 单挑生命/气力/闪避/伤害开关分别验证，确认剧情强制胜败仍能执行。
7. 回想顺序与上限、新单挑清空；属性和好感编辑只在允许场景可用，失效对象不能继续应用。
8. 精确恢复适配完成后，再加入对白/普通选择/计时选择/轮盘/命运分配/单挑回合的真实存读闭环、损坏拒绝与中止测试。
