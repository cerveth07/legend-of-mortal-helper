# 活侠·万象录（独立重写版）

一个《活侠传 / Legend of Mortal》的整合 Mod。

主要功能：

- **天命控骰**：在游戏原生判定页指定点数，或直接点击想要的选项（自然掷骰 / 指定点数 / 直接选项三态）。
- **选项提示与分支记录**：悬停选项查看原生条件与已确认效果；选项上标注〔已走〕〔未记录〕。
- **单挑对白回看**：记录本场/最近一场单挑的实际对白，最多 500 条，不暂停战斗。
- **战斗辅助**：单挑七项（生命、气力、闪避、必定命中、必定先手、造成伤害降为0、一击必杀）、群战五项，可分别开关。
- **养成辅助**：练功与锻造炼丹消耗不减、「快速」一次完成一级、无限日常行动点、最高好感。
- **存档扩展**：存档格数 2–999、槽位备注（`F2`）、按最近存档排序（`F3`）。
- **精确恢复（实验）**：记录检查点（基线存档 + 骰子/选项事件）并可回放；播放按「脚本名 + 选项文本 / 判定序号」校验，实机未验证。
- 常见数值编辑：属性（26 项白名单）、物品数量、游戏速度（0.25～5 倍）、解除修炼点数消耗上限。
- 人际关系：好感编辑与心上人指定。

当前为 **0.1.0 开发候选**：适配 Steam Build 26021712、Unity 2020.3.49f1、BepInEx 6.0.0-be.692（Mono / x64）。仓库当前为**私有**、未发布安装包；源码为独立实现，不包含第三方 Mod 的代码、二进制或游戏资产，因此公开不依赖上游授权（是否公开由作者决定）。编译 + 248 项离线断言 + 启动级与部分无头功能验证通过（指定点数注入、存档备注、分支记录、游戏速度、存档格数、提示解析），但**战斗、养成与存档界面等仍未逐项实机验收**，详见 [验证记录](docs/VALIDATION.md)。

本工程按功能规格重写（插件标识 `cerveth.mortal.helper`），不引用旧 `MortalFateHelper.dll` 或 `LOMSave2.dll`；界面按原作者设计复刻，功能实现为重新编写。开发过程与来源见 [PROVENANCE.md](PROVENANCE.md)，外部依赖见 [THIRD_PARTY.md](THIRD_PARTY.md)；不声称是未经接触旧代码的洁净室开发，也不构成版权零风险证明。

## 一、功能与用法

`Tab` 打开/收起面板。界面分五页：**剧情辅助 / 战斗辅助 / 养成辅助 / 数值编辑 / 存档设置**；`剧情辅助` 下有「单挑回想」子页，`养成辅助` 下有「人际关系」子页。收起后左侧是竖排「萬象錄」徽章，点击展开、可拖动并记忆位置。底部滑杆调界面透明度（40%～100%），窗口四边/四角与右下握把均可拖拽缩放，标题栏可拖动移动。

### 1. 剧情辅助

| 功能 | 用法 | 默认 | 限制 |
|---|---|---|---|
| **天命控制（控骰）** | 三态：`自然掷骰` / `指定点数` / `直接选项`。指定点数模式下可编辑「基础点数」（默认 50），点原生启动即用该点数；直接选项模式下在判定页点目标选项即可。 | 自然掷骰 | 点数按每次判定的 `diceMin`～`diceMax` 校验，越界不扣命运点；重掷仍走原生命运点；动画期间禁止重复提交；判定页始终提供重掷/范围阶段，所以零命运也能直接点选项 |
| **选项提示（含剧透）** | 收起面板后悬停选项，分三段：`选择条件`（游戏原生条件文本）、`选择效果（已确认部分）`（脚本里能确定的直接调用）、`取决于判定的后果`（分支点 `checkpointmanager.Switch`、后续剧情 `luamanager.SetNextScript` / `statmodifymanager.AddStory`）。总开关与两个子项独立。 | 全关 | 受限词法解析：遇到未知调用、条件分支、非字面量参数即停止分析；注释掉的调用不计入；每段最多 6 条，不猜 |
| **分支记录** | 打开「显示已走分支标记」后，选项右上角显示 `〔已走〕` 或 `〔未记录〕`，点击时记录。面板底部列出最近记录，可「清空记录」。 | 关 | 记录键为「脚本名 + 选项文本」，存配置目录 `cerveth.mortal.helper.choices.txt`，**不写入存档** |
| **精确恢复（实验）** | 记录侧：开始记录 → 游玩（记录原始骰子点数与选项点击）→ 保存检查点，写到配置目录 `mhr\slot-00N.mhr`。播放侧：恢复检查点 → `RecoveryController` 预检 → 载入基线（`ExecuteLoadGameData` + `SaveUniverseData` + `UpdateCheckMissions` + `LoadCurrentScene`）→ 按记录注入 → 事件全部消费后比对状态摘要。 | 关 | **播放链路实机未验证**；恢复会覆盖当前内存进度（未存进度会丢），使用前请先正常存档；事件 key 不一致、场景切换或 120 秒没有匹配交互都会立即中止并说明原因；旧版（自增序号 key）检查点不兼容 |
| **剧情诊断** | 切换剧情脚本时在「上次操作」显示脚本名与本段可对应分支数。 | 关 | 纯提示 |
| **检查点更新提醒** | 剧情标记（flag）变化时提示 `检查点更新：名称=值`。 | 关 | 这是剧情标记，不是存档点 |
| **单挑回想**（子页） | 记录本场/最近一场单挑实际调用的对白，最多 500 条，新单挑开始时清空。 | — | 回想不暂停游戏 |

### 2. 战斗辅助

全部默认关闭，单挑与群战分组互不混用。

**单挑（回合制，`Mortal.Combat`）**

| 开关 | 效果 |
|---|---|
| 主角生命不减少 | 阻止战斗扣血与持续伤害；保留剧情直接改值与强制胜负 |
| 单挑无限气力 | 保持行动所需气力，不修改周目内力属性 |
| 主角最高闪避率 | 闪避率拉到上限；不能避开必中特技或剧情结果 |
| 主角必定命中 | 敌方基础闪避失效，主角攻击不会落空（只提高命中） |
| 主角必定先手 | 行动对比判定主角成功、敌方失败：主角先出手，敌方本回合行动失效 |
| 造成伤害降为0 | 敌方受到的伤害归零（含持续伤害），主角打不掉敌人血；与「一击必杀」互斥 |
| 敌方受到有效伤害时一击必杀 | 敌方有效受伤时耗尽生命；自动附带必定命中与必定先手 |

**群战（即时战斗，`Mortal.Battle`）**

| 开关 | 效果 |
|---|---|
| 主角生命不减少 | 仍可能硬直；友军与剧情强制退场沿用原生规则 |
| 主角气力保持充足 | 作用于群战气力条 |
| 群战技能栏立即冷却 | 保留原生施放限制与演出 |
| 冻结群战剩余时间 | 倒计时维持最大值；**靠计时归零获胜的关卡请关闭** |
| 敌方受伤即倒地 | 含友军攻击与持续伤害；保留敌方闪避与剧情无敌，不影响中立与友方 |

### 3. 养成辅助

| 开关 | 效果 | 默认 |
|---|---|---|
| 练功消耗不减 | 练功结束后把武学点数恢复到操作前的值；修炼条件仍须满足 | 关 |
| 快速练功 | 把本次消耗换成「当前级剩余点数」，一次完成一级；升级奖励照常 | 关 |
| 锻造炼丹消耗不减 | 操作结束后把点数与金钱恢复到操作前的值；不解锁研发 | 关 |
| 快速锻造炼丹 | 同上，一次完成当前级 | 关 |
| 无限日常行动点 | 行动点至少为 1 且不减，日期不会因行动用完自动推进 | 关 |
| 最高好感 | 已登场角色维持各自好感上限；不解锁未登场角色 | 关 |

**人际关系**（子页）：好感编辑（仅已登场角色，0～各自上限，应用前复核当前值）；心上人（九位候选 + 自己，写入 `GameStatType.愛人`，不补齐结缘事件）。

### 4. 数值编辑

| 功能 | 用法 | 限制 |
|---|---|---|
| 属性编辑 | 26 项白名单（金钱/个人贡献/门派资产…拳掌/暗器/刀剑/轻功…），支持筛选；应用前复核对象与当前值 | 仅在「自由活动」场景空闲、无原生面板占用时可用 |
| 物品数量 | 可直接编辑「游戏物品面板里选中的物品」；也可按四类（书籍/杂物/贵重品/消耗品）列表选择，支持筛选 | 默认只列已有物品，勾选「也列出数量为 0 的物品」才可生成；范围 0～999999 |
| 游戏速度 | 0.25～5 倍滑杆 + 「恢复 1 倍」 | 只改 `Time.timeScale`，不接管原生暂停/慢动作；插件卸载时还原为 1 |
| 解除修炼点数消耗上限 | 练功面板不再限制单次消耗，按现有武学点数扣减 | 保留修炼条件与升级奖励 |

### 5. 存档设置

| 功能 | 用法 | 说明 |
|---|---|---|
| 存档格数 | 输入 2～999 后点「保存格数」，重新打开存档/读档界面生效；填 0 或「恢复默认」用游戏原值 | 只改变列表建多少个槽位，**不改动任何存档文件** |
| 存档备注 | 在游戏存档列表选中槽位后按 `F2`，面板跳到本页编辑；备注显示在槽位标题下方 `〔备注〕…` | 存配置目录 `cerveth.mortal.helper.slots.txt`（旧版放在存档目录，本版不改动存档目录） |
| 按最近存档排序 | `F3` 切换 | 仅重排读档列表行顺序，槽位编号与文件不变 |

### 快捷键

| 键 | 作用 |
|---|---|
| `Tab` | 展开 / 收起面板（可在配置里改） |
| `F2` | 已选中存档槽位时，打开「存档备注」编辑 |
| `F3` | 切换「按最近存档排序」 |

## 二、安装

发行包分两种，**都不需要安装器**：文件放进游戏目录就生效。要求 Windows x64 + 正版游戏。

| 包 | 适用 | 做法 |
|---|---|---|
| **整合包**（`活侠万象录-<版本>-full.zip`，约 0.6 MB） | 没装过 BepInEx 的人 | 解压后把里面的**全部内容**复制进游戏根目录（与 `Mortal.exe` 同级），允许合并 |
| **仅插件包**（`-plugin.zip`，约 57 KB） | 已有 BepInEx 6 Mono 的人 | 把 `BepInEx\plugins\cerveth.mortal.helper\MortalHelper.dll` 放进现有 `BepInEx\plugins\` |

整合包内含 BepInEx 6.0.0-be.692（Unity Mono x64，LGPL-2.1，来源与许可见包内「第三方组件说明」）与本插件。

**已验证**：把游戏目录原有的加载器整组移走后，只解压整合包即可正常启动并加载插件（日志 `活侠·万象录 0.1.0 初始化完成`）。

制作与自建包：
```powershell
python build.py --game "<游戏目录>" --loader "<BepInEx core 目录>" --compiler "<csc.dll>" --test
python tools\package.py --plugin artifacts\MortalHelper.dll --loader "<含 winhttp.dll 的加载器目录>" --out dist
```

如果你更愿意自己装：
1. **完全退出游戏**，把存档目录整体备份（通常为 `%USERPROFILE%\AppData\LocalLow\Obb Studio\Mortal\<SteamID>`）。
2. 安装 [BepInEx 6.0.0-be.692](https://github.com/BepInEx/BepInEx)（Unity Mono x64）到游戏目录：解压后应存在 `winhttp.dll`、`doorstop_config.ini`、`.doorstop_version`、`BepInEx\`。
3. 把 `MortalHelper.dll` 放进 `BepInEx\plugins\`（子目录也可以，例如 `BepInEx\plugins\cerveth.mortal.helper\`）。
4. 从 Steam 启动游戏，等待加载完成后按 `Tab`。

正确层级：

```text
LegendOfMortal/
├─ Mortal.exe
├─ Mortal_Data/
├─ winhttp.dll
├─ doorstop_config.ini
├─ .doorstop_version
└─ BepInEx/
   ├─ core/
   └─ plugins/
      └─ MortalHelper.dll
```

**冲突提示**：若 `plugins` 里仍有 `MortalFateHelper.dll`、`LOMSave2.dll`、`DiceMaster*.dll`、`ControlMyDestiny.dll`，本插件会在启动时停用自己并在日志里报冲突——请先把旧插件移出游戏目录。

## 三、备份、升级与卸载

- **备份**：退出游戏后复制完整存档目录、`BepInEx\config`（含本插件的 `cerveth.mortal.helper.cfg`、`*.choices.txt`、`*.slots.txt`、`mhr\`）、以及 `BepInEx\plugins` 下的插件。
- **升级**：替换 `MortalHelper.dll` 即可；配置与记录文件保留。
- **卸载**：整合包装的删掉 `winhttp.dll`、`doorstop_config.ini`、`.doorstop_version` 与整个 `BepInEx\`；仅插件包装的只移走 `MortalHelper.dll`。配置与记录在 `BepInEx\config\cerveth.mortal.helper.*`，留着即可。存档不受影响；关闭开关 **不会** 撤销已写入的数值，也不会删除已保存的备注/分支记录。

## 五、已知限制与未实现

- **未实现**：强制事件 / 取消待执行事件与任务（旧版通过替换 Lua 待执行队列实现，会跳过剧情前置条件）；「自动选择固定分支」；一键安装器；旧版 `.loms` / `.duel` 附加档的迁移读取。
- **恢复功能仍是实验**：记录与播放都已接线（播放走 `RecoveryController`：预检 → 基线 → 重放 → 校验），但**播放未实机验证**；基线取自当前内存存档数据，可能落后于实际剧情位置；基线还原时 `FreeRandomState` 不会恢复，重放不保证自由场景随机一致。
- **验证到什么程度**（详见 [验证记录](docs/VALIDATION.md)）：

  | 已验证 | 未验证 |
  |---|---|
  | 指定点数注入（判定范围 0～99 时注入 37 → 掷出 37） | 重放注入全链路 |
  | 存档备注写入与回读、分支记录与真实菜单上的「已走」标记 | 单挑 / 群战各开关 |
  | 游戏速度、存档格数配置生效 | 养成辅助各开关 |
  | 真实剧本上的选项提示与后果解析 | 存档界面实际槽位、`F2` / `F3` |
  | 基线存档可无损载回、载入后可进剧情 | 数值编辑实际落值 |
- **存档安全**：不要加载来源不明的存档；本插件的 `mhr` 记录只用于自身恢复，不替代原生存档。
- **`Diagnostics/SelfTest` 是开发用探测**：开启后会载入槽位 3 并自动推进剧情（只调游戏 API，不动鼠标），正常游玩请保持关闭。
- **仓库为私有**：公开与否由作者决定。旧整合版曾打包第三方 DLL，本仓库没有引入，因此不承担其许可证义务；也正因如此，旧版用户无法用本仓库直接替换旧插件包。

## 六、构建与测试（开发）

需要 Windows、Python 3、.NET 8 运行时、Roslyn 4.12 `csc.dll`、本机游戏，以及 BepInEx 6.0.0-be.692 Mono 的 `core` 目录。脚本不下载依赖，也不安装到游戏。

```powershell
python build.py --game "D:\steam\steamapps\common\LegendOfMortal" `
                --loader "本地\BepInEx\core" `
                --compiler "本地\Roslyn\tasks\netcore\bincore\csc.dll" --test
```

- 产物输出到被 Git 忽略的 `artifacts/`，构建记录含源码与本机依赖的 SHA-256，不含游戏程序集。
- `tools/check_source.py`：检查源码/文档目录没有游戏或旧插件二进制、旧命名空间、`BinaryFormatter`。
- `tools/provenance_scan.py`：与旧仓库源码做 token shingle 与最长公共片段比对（启发式，非法律结论）。
- 离线断言：`tests/Contracts.cs`（当前 248 项，0 失败；只用人工数据与临时目录，不读取玩家存档）。
